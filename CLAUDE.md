# CLAUDE.md — Project Conventions

Read this before making changes. This file exists so Claude behaves consistently
whether it's running in VS Code on the Mac, Claude Desktop, or Claude Code on mobile.

## Project

AI-Powered Equity Filings Summarization & Risk Insight Agent — a notebook-driven
pipeline that loads a synthetic filing, chunks it by section, generates an
analyst-style report (Highlights / Risks / Tone), and evaluates it with proxy
metrics (groundedness, sentiment agreement, coherence).

Full design reference: `docs/project-plan.md` (source of truth for architecture —
if this file and that one disagree, the plan doc wins; flag the conflict instead
of guessing).

## Non-negotiable rules

1. **Never hand-edit the stats block in README.md.** It's generated by
   `scripts/check_docs_sync.py --write`. If you change anything that affects
   filing count, chunk count, or test count, regenerate it — don't type numbers in.
2. **Pipeline logic lives in `scripts/` and the top-level packages, never in
   notebook cells.** The notebook (`notebooks/demo_runner.ipynb`) only imports
   `scripts.run_pipeline.run()` and displays results. If you find yourself writing
   real logic inline in a notebook cell, stop and move it to a module.
3. **Run `pytest` before every commit.** Don't commit if tests are red.
4. **Run `python scripts/check_docs_sync.py` before every commit** if you touched
   data files, tests, or README. CI will catch it anyway, but catch it locally first.
5. **Always `git pull` before starting work, and push before ending a session.**
   Uncommitted local state on one device is invisible to the other — treat GitHub
   as the only source of truth, not local disk.
6. **No native/compiled dependencies.** This project intentionally avoids
   FAISS/sentence-transformers-style deps to keep `pip install` identical on
   Mac and Windows. If a task seems to need one, flag it before adding it.
7. **All paths via `pathlib.Path`. All file I/O uses `encoding="utf-8"` explicitly.**
   No hardcoded `/` or `\`, no relying on platform default encoding.

## Module layout (don't reorganize without updating this file)

```
loaders/base.py                  BaseLoader interface
loaders/synthetic_loader.py      reads data/synthetic_filings/*.json
loaders/pdf_loader_adapter.py    future real-PDF swap (not wired in by default)
chunking/section_chunker.py      Document -> list[Chunk]
summarizer/prompt_builder.py     builds Claude prompt from chunks
summarizer/claude_client.py      Anthropic SDK wrapper, has MOCK_LLM mode
scoring/lexicon_scorer.py        tone + uncertainty scoring
scoring/risk_extractor.py        pulls risk-heavy snippets
evaluator/groundedness.py       substring-coverage proxy
evaluator/agreement.py          predicted tone vs gold label
evaluator/coherence.py          bullet-count/length checks
scripts/run_pipeline.py          run(doc_id) -> (Report, EvalResult) — single entrypoint
scripts/check_docs_sync.py       docs-sync enforcement (see rule 1)
notebooks/demo_runner.ipynb      the actual deliverable
evaluation/sample_summary.json   REQUIRED output artifact (brief's exact path — not code)
evaluation/eval_note.md          1-2 page evaluation note (required deliverable)
tests/                           mirrors the module layout above
```

**Note:** `evaluator/` (code) and `evaluation/` (output artifacts) are deliberately
separate — `evaluation/` is reserved for the exact deliverable path the brief
specifies (`evaluation/sample_summary.json`). Don't put code in `evaluation/` and
don't put run artifacts in `evaluator/`.

## Testing conventions

- Unit tests are deterministic, no network calls.
- Integration test of the full pipeline runs with `MOCK_LLM=true` by default.
- Real-API tests are marked `@pytest.mark.live_llm` and skipped unless explicitly run.
- Before submission, the notebook must be executed top-to-bottom with outputs
  preserved (`jupyter nbconvert --execute --to notebook --inplace notebooks/demo_runner.ipynb`).

## Environment

- Python 3.11+, dependencies in `requirements.txt`.
- `.env` controls `LOADER_MODE`, `CLAUDE_MODEL`, `MOCK_LLM` — see RUNBOOK.md for
  both bash (Mac) and PowerShell (Windows) setup commands.

## When in doubt

Prefer asking or flagging over guessing on: docs-sync script behavior, adding any
new dependency, or changing the loader/chunker interface (it's the contract the
"swap to real PDFs later" requirement depends on).
